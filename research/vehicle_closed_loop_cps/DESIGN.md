# Closed-loop cyber-physical simulation scope
User decision, 24 October 2026: physical hardware validation is outside the completion scope. Complete the computational security project before manuscript writing.
Use SUMO 1.27.1 with existing frozen command-refined scene estimators. The controller receives only packet-derived ego speed, lead speed and gap. Simulator truth is available only to packet generation and the separate evaluator.
Add a separately signed synthetic radar domain carrying gap and relative speed. Proposed controllers require consistent signed scene/radar intervals and use an IDM-form nominal command with a conservative discrete braking-reserve filter. Commands pass an authenticated actuator gate; observations remain conditional on declared sensor and execution bounds.
Compare raw sensor control, sensor-authenticated control, learned estimation without the control filter, and proposed controllers with midpoint/learned estimation. Freeze profiles, new seeds, attack definitions and code before confirmation runs. Do not retrain on these runs.
Inject sensor bias, signature tampering, signed scene/radar disinformation, replay, dropout, actuator-message tampering, untrusted advisory instructions, execution failure and risk changes. Shared scene/radar corruption remains a declared limitation, not an omitted result.
Provide operator evidence cards with source status, cause, action and stopping margin. Ignore advisory instructions in the proposed policy. This models an untrusted instruction channel; do not infer human persuasion resistance or measured human trust.
Alternatives considered: leave ideal controller context (does not address the identified gap); add a full camera/LiDAR rendering stack (not needed for this numerical control/security question); extend existing SUMO and frozen estimator interfaces (selected).
EAAI topic fit will be documented against publisher sources. Keywords are topics, not a requirement to invent a separate human study or cover every keyword. The specific research claim is the command/context-aware policy and its measured computational behavior, not first-ever residual learning or unconditional safety.
